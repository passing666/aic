## 2. exp003 说明了什么

### 2.1 训练不足假设得到支持

exp003 只增加训练轮数，validation mIoU 从 `0.762585` 提升到 `0.779112`，8 个有效类别全部提升。因此，exp002 在 30 epoch 时确实没有充分优化，训练时长是一个真实有效的变量。

提升并非只来自 Barren：

- Vehicle：`+0.034164`
- Background：`+0.026610`
- Agricultural：`+0.016495`
- Barren：`+0.015101`
- Road：`+0.012712`
- Building：`+0.011188`
- Water：`+0.009968`
- Vegetation：`+0.005982`

因此不能把下一轮简单定义为“只救 Barren”。exp003 的收益是整体性的，尤其 Vehicle 和 Background 提升明显。

### 2.2 仍然不能认为已经收敛

第 60 轮仍然刷新最佳，但后半程存在波动：

- epoch 31-40 平均 mIoU：`0.761664`
- epoch 41-50 平均 mIoU：`0.767149`
- epoch 51-60 平均 mIoU：`0.768928`
- epoch 60：`0.779112`

后半程均值逐步提高，支持继续优化；但最后一轮高于区间平均值较多，说明单轮峰值和稳定水平仍有差别。当前可以把 60 epoch 作为新基准，但不应直接假设 80 或 100 epoch 必然继续同比提升。

### 2.3 排行榜泛化仍是最大未知数

exp002 的 validation mIoU 为 `0.762585`，test_1 官方 mIoU 只有 `0.591572`，差距约 `0.171`。exp003 的本地提升证明优化有效，但不能证明线上也会增加 `0.0165`。

目前还没有 exp003 的 test_1 成绩，所以 exp003 现在只能称为新的**本地验证基准**，不能称为新的比赛基准。

## 3. 已完成的推理与鲁棒性检查

### 3.1 推理策略对比

使用相同的 exp002 checkpoint，在固定 validation 上得到：

| 推理方式 | mIoU |
|---|---:|
| 768 resize | `0.762739` |
| 原生 1024 全图 | `0.740970` |
| 768 滑窗，stride 512 | `0.737083` |

当前模型是在 768 输入配方下训练的，768 resize 明显优于另外两种策略。因此下一次 test_1 推理继续使用 768 resize，不切换到 1024 全图或滑窗。

### 3.2 简单颜色偏移检查

使用 exp002 checkpoint 对 validation 施加受控颜色变化：

| 场景 | mIoU | 相对原始 |
|---|---:|---:|
| 原始输入 | `0.762584` | 基准 |
| 亮度 × 1.10 | `0.762258` | `-0.000326` |
| 亮度 × 1.10、对比度 × 1.05 | `0.761267` | `-0.001317` |

简单亮度/对比度变化只造成很小下降，不能解释 test_1 的巨大差距。因此“只增加亮度增强”不应被当成当前第一优先级。

这并不代表所有域偏移都不存在。test_1 可能存在更复杂的场景、纹理、尺度、阴影、色温或地理分布变化；只是目前的简单 stressed validation 没有证明全局亮度是主要瓶颈。

## 4. 下一步第一任务：提交 exp003

使用 exp003 的 epoch 60 `best_model`，完全复用 exp002 的推理链路生成 test_1：

原图 1024 x 1024

提交前必须记录：

- PNG 尺寸、模式和像素范围检查结果；
- zip SHA-256；

这次提交的目的不是刷排行榜，而是回答一个实验问题：**延长训练带来的本地提升能否转化为 test_1 泛化提升。**

## 5. exp003 提交结果的分流决策

### 情况 A：test_1 明显提升

如果 exp003 相比 `0.591572` 有明确提升，说明训练时长收益能够部分迁移到 test_1。下一轮建议测试学习率调度：

- 训练 60 epoch；
- batch size 保持 2；
- 初始 learning rate 保持 `6e-5`；
- warmup 2 epoch；
- 之后使用 cosine decay；
- 其他参数全部保持 exp003 不变。

scheduler 只作为唯一主要变量，不能同时修改 batch、初始学习率、增强或 loss。

### 情况 B：validation 提升但 test_1 基本不变

这说明继续优化随机 validation 的收益不能有效迁移到测试域。下一轮应优先建设更接近 test_1 的验证代理：

- 颜色、gamma、色温和饱和度扰动；
- 阴影、局部对比度、轻度模糊和压缩扰动；
- 按图像特征或场景相似度构造 group split；
- 对 test_1 三联图做人工场景归类；
- 训练时加入受控颜色和尺度增强。

此时不应继续单纯把 epoch 从 60 延长到 80 或 100。

### 情况 C：test_1 下降

如果 exp003 线上低于 `0.591572`，应保留 exp002 作为线上基准，怀疑更长训练加强了对随机 validation 分布的拟合。下一轮优先测试增强和 group/stressed validation，不再继续无调度长训练。

## 6. 后续实验顺序

### exp004：学习率调度或泛化增强，二选一

exp003 排行榜结果出来后再决定：

- 线上同步提升：exp004 只加入 warmup + cosine；
- 线上不变或下降：exp004 只加入受控颜色/尺度增强。

不建议预先把 scheduler 和增强合并，因为那会失去归因能力。

### exp005：类别不均衡策略

在 exp004 结果稳定后，再从下面三者中选择一个：

1. CE + 温和 Dice；
2. 温和类别权重；
3. 含 Barren 样本的受控过采样。

Barren 在 test_1 预测中约占 `0.620%`，低于训练集 GT 的约 `1.746%`，但不是完全不输出。当前没有充分证据直接使用激进类别权重。每个类别策略都必须同时观察总 mIoU、Barren、Vehicle、Background 和 Building。

### exp006：模型容量

只有在训练时长、推理策略、增强和 loss 方向稳定后，才比较 MIT-B1/B2。模型升级必须作为独立变量，不能与 Dice、类别权重或颜色增强同时加入。

## 7. 当前不建议做的事情

- 不把 1024 全图或滑窗直接作为下一次提交方案；
- 不把简单 brightness/contrast 增强当作解决 `0.171` 差距的主要方案；
- 不同时改变 batch、学习率、warmup、scheduler、epoch、增强和 loss；
- 不依据 test_1 预测占比直接使用极端类别权重；
- 不在没有 exp003 线上结果前继续追加 80/100 epoch；
- 不把单次排行榜分数当作训练集标签使用；
- 不删除 exp002，保留它作为当前已知线上基准。

## 9. 结论

exp003 是目前最重要的正向实验：仅延长训练就让固定 validation mIoU 从 `0.762585` 提升到 `0.779112`，且 8 类全部提升。它证明了训练不足是真实问题，但还没有证明它能解决 test_1 的泛化差距。

因此当前唯一正确的下一步是：**用 exp003 epoch 60 按已验证的 768 resize 推理方案提交一次，获得线上方向性证据；之后根据线上结果，在 scheduler 和泛化增强之间做单变量选择。**
