## 三、P0：必须先统一评价口径

### 问题

`SegmentationDataset` 使用同一个 `image_size` 同时缩放输入图像和 GT Mask：

```python
image = image.resize((self.image_size, self.image_size), Image.Resampling.BILINEAR)
mask = mask.resize((self.image_size, self.image_size), Image.Resampling.NEAREST)
```

因此：

- exp001 在 512×512 GT 网格上计算 mIoU；
- exp002 在 768×768 GT 网格上计算 mIoU；
- 官方原始图像和 Mask 为 1024×1024。

这意味着两次实验不仅改变了模型输入尺寸，也改变了评价像素网格。小目标、边缘和细线区域会受最近邻缩放影响，当前 `+0.0131979` 是积极信号，但还不是严格控制变量后的最终结论。

### 正确复核方式

不需要重新训练，分别加载两个最佳模型：

1. exp001 图像输入仍为 512×512；
2. exp002 图像输入仍为 768×768；
3. 两者输出 logits 都上采样到 1024×1024；
4. 两者都与原始 1024×1024 GT Mask 比较；
5. 两者使用同一份 `val.csv`、同一套 Ignore 掩码逻辑；
6. 输出统一记录总 mIoU、8类 IoU和有效像素预测为 Ignore 的比例。

只有统一复核后，才能决定768是否正式替代512基线。原有结果不得删除，应保留为审计对照，并明确标注为“原评价尺寸口径”。

## 五、其他工程风险

### P0：尚无正式推理与提交自检链路

仓库中没有 `predict.py` 或等价脚本，也没有提交检查器。至少需要自动验证：

- 输出数量和测试图片数量一致；
- 文件名与测试图片完全同名；
- 输出为1024×1024；
- 输出为单通道、非 Palette PNG；
- 像素值只包含合法类别 ID；
- 最终压缩包目录结构正确。

在该链路打通前，即使验证集继续提升，也不能保证能够形成有效提交。

### P1：训练不支持真正断点续训

当前脚本逐轮保存 JSON 记录，但没有保存可恢复的 `last` 模型、优化器、AMP Scaler 和调度器状态，也没有 `--resume`。训练中断后能够看到历史记录，但不能从中断轮次继续训练。

### P1：exp002 后期波动明显

exp002 的 Epoch 26～30 mIoU 依次为：

```text
0.75497, 0.71779, 0.75542, 0.75618, 0.76258
```

Epoch 27 单轮下降约 `0.03719`，随后恢复。训练 Loss 仍总体下降，说明训练没有崩溃，但恒定学习率下模型参数存在明显波动。统一1024评价通过后，学习率调度是合理的下一单变量实验。

### P1：README训练命令可能误导

README 中示例输出目录名包含 `exp002`，但命令没有提供 `--image-size 768`，照抄时仍会使用默认512。每条训练命令必须显式写出实验的唯一变量和完整关键参数。

### P2：仓库整洁与复现性

- `docs/suggestions/` 中存在两份不同版本的 `exp001_team_suggestions.md`，容易让人或AI读取旧版本；
- mIoU逻辑分散在多个位置，存在以后再次漂移的风险；
- `smoke_test.py` 的 CrossEntropy 没有使用 `ignore_index=0`，与正式训练口径不一致；
- `requirements.txt` 没有锁定版本；
- `run_config.json` 没有记录Python、PyTorch、Transformers、CUDA版本和Git提交号。
