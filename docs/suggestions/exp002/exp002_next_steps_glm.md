## 二、优先级排序与理由

结合"预期收益 × 确定性 ÷ 成本"，建议按以下顺序做。前三项是低风险高确定性，应优先完成。

### P0-1：exp003 = 学习率调度 + 增大 batch（训练配方修正）

这两项本质都是"修正训练配方"，建议作为一个实验合并加入（团队的一变量原则可以保留给模型/损失/增强类改动）：

- batch size 从 2 提到 8～16（先跑一个 batch 显存试探脚本；5090 上 B0@768 大概率能到 16）。
- 学习率随 batch 线性放大，例如 bs8 → 2.4e-4 左右。
- 加 warmup（前 1～2 epoch 线性升温）+ cosine 或 poly 衰减到终点。
- epoch 延长到 60～80（每 epoch 耗时会因大 batch 略增，但总时间仍可控，且 5090 目前大量闲置）。

预期：仅这一项就有较大概率把 mIoU 推到 0.78+，因为"最佳轮次=最后一轮"是训练不足的直接证据。这也是赛题官方建议里最常规、最稳的改进。

### P0-2：推理与提交链路（赛题硬性要求，比刷分更紧急）

初赛提交格式错一处就是零分，复赛起还要 Docker 复现。建议在 exp003 训练期间并行完成：

1. `src/predict.py`：对 `test_1/images` 的 500 张 1024×1024 图做推理，输出单通道、无调色板、像素值 0-8、文件名一致的 PNG。
2. 推理时不要把 1024 整图 resize 到 768 再放回——建议滑动窗口（如 768 窗口、stride 512、重叠区取平均 logits），或至少做"resize 到 768 推理 + logits 上采样回 1024 argmax"并与滑窗版本对比，选验证集上更高者。
3. 提交自检脚本：检查尺寸、模式（`P`）、像素值范围、文件数、命名。
4. 尽早用当前 best_model 对 test_1 做一次完整提交演练（哪怕分数一般），走通全流程。

### P1-1：exp004 = 更大骨干网络（MIT-B2，单模型合规）

赛题只禁止多模型集成，不限制单模型大小（推理时间/模型大小"合理"即可）。在 batch/调度修正后，B0 → B2（或 B3）是最可靠的结构性提升。5090 32GB 完全撑得住 B2@768、bs8。注意：

- 用学术公开权重（`nvidia/mit-b2`），合规。
- 学习率建议比 B0 略低（如 1e-4 级别），并保持与 exp003 相同的调度形态。
- 记录推理耗时，确认单张 1024 推理在秒级即可，不用担心。

### P1-2：exp005 = 数据增强针对域偏移（赛题核心考点）

赛题明确说测试集分三次发布、分布不同，且农田水体占比偏高。当前只有水平翻转，建议加入（一次实验内成组加入标准增强，属于常规做法）：

- 几何：随机缩放 crop（0.5～1.25）、水平+垂直翻转、小角度旋转。
- 颜色：亮度/对比度/饱和度抖动、轻度 HSV 扰动（域偏移的主要手段）。
- 可选：轻微高斯噪声/模糊。

增强是跨测试集稳定性的关键，半决赛用 1+2+3 合并计分，"每次都稳"比"单次高分"更重要。

### P1-3：exp006 = 损失函数针对类别不均衡

Vehicle 像素占比 0.78%、IoU 0.727，Barren 0.544 是全表最低。建议：

- CE + Dice（按 1:1 或 CE 权重 0.75）作为一组实验；
- 若 Vehicle/Barren 仍无改善，再单独试温和类别权重（按像素占比开方反比，避免过猛）。
- 不建议一上来就 Focal Loss，调参敏感，先 Dice。

### P2：推理期优化（合规、零训练成本）

- TTA：水平+垂直翻转三视图平均（单模型 TTA，赛题明确允许）。
- 滑动窗口重叠平均（见 P0-2）。
- 8 通道标签重映射（0→255 ignore，1-8→0-7）：消除模型把像素预测为类别 0 的自由度。exp001 修复审查显示当前预测为 0 的比例是 0，收益可能有限，优先级放低。

### P3：更远期

- 1024 原生分辨率训练（配合大 batch，收益与成本都要实测）。
- 半决赛前用全部 6996 张训练（不留验证集，或只留极小验证集用于早停参考），这一步在确定最终配置后做，预期有小幅提升。

## 三、明确不建议做的

1. **任何形式的模型集成**——直接违反赛题，取消成绩风险。
2. **外部数据/闭源权重**——违规。
3. **用 test_1 反馈调参刷分**——test_1 只用于初赛通过（mIoU>0 即进复赛），且初赛不计分；把精力花在复赛/半决赛的泛化上更值。
4. **一次叠加多个大变量**（如 B2 + Dice + 全套增强同时上）——一旦掉分无法归因。团队现有的一变量纪律是对的，只有 P0-1（batch+调度）建议合并，因为它们同属"训练配方缺陷修正"。
