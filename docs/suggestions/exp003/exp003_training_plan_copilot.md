## 2. 综合判断

### 2.1 主要问题是泛化，不是单纯没有训练够

exp002 的最后一轮仍刷新最佳，说明继续训练有必要验证；但它不能解释 0.171 的全部差距。延长训练只能回答“优化是否不足”，不能自动消除 test_1 的分布变化。

当前应同时保留两个假设：

1. **训练不足**：exp002 仍可能从更长训练中获益。
2. **域偏移**：test_1 比随机验证集更亮，且预测分布显示 Barren 几乎消失、Vegetation 被低估、Building 被高估；这更像测试域变化和颜色鲁棒性不足。

因此，不应把 batch、学习率缩放、warmup、scheduler、长训练、增强和 loss 一次合并。那样即使排行榜上涨，也无法判断原因。

### 2.2 最需要关注的类别

GLM 从 42 张预测图抽样得到的 test_1 预测占比曾给出较强异常信号，但全量 500 张重新统计后，以下数字应以全量结果为准。这些是真实预测分布，不是 test_1 的 GT 分布：

- Barren 预测约 0.620%，训练集 GT 约 1.746%，明显偏低，但不是接近完全不输出。
- Vegetation 预测约 27.382%，训练集 GT 约 28.413%，全量上接近训练分布。
- Building 预测约 20.523%，训练集 GT 约 18.154%，有一定过预测，但弱于抽样结论。
- Vehicle 预测约 0.644%，训练集 GT 约 0.778%，略低，仍需看小目标形态。

全量预测统计保存在 `outputs/analysis/test1_submission_exp002/submission_prediction_distribution.json`。test_1 抽样平均 RGB 比训练集约亮 10 个灰阶；这个证据仍支持颜色增强，但颜色统计和预测占比都不能替代 test_1 真值评价，也不能据此精确分解每一类的 mIoU 损失。

### 2.3 验证集没有被证明错误，但不够代表比赛

已有审计排除了 ID 重复、完全相同图片等问题；GLM 的相邻 patch 像素差检查也没有发现明确的相邻泄漏。因此，0.7626 可以作为随机同分布验证成绩。

但随机划分不能保证代表 test_1。后续必须增加 stressed/group 验证，避免只优化一个过于友好的随机 val。

## 3. 统一优先级

### P0：先做零训练诊断

1. 对 test_1 生成 20 张原图、预测 mask、彩色叠加三联图。
2. 统计全部 500 张预测类别占比，而不是只依赖 42 张抽样。
3. 选择同一个 exp002 checkpoint，在 validation 上比较：
   - 当前 768 全图 resize 推理；
   - 1024 全图推理；
   - 768 窗口、原图尺度滑窗推理；
   - 合规时再比较水平/垂直翻转 TTA。
4. 为每种推理策略记录总 mIoU、每类 IoU、预测 Ignore 比例、显存和耗时。

这一步的目标是确认问题中有多少来自推理分辨率和边界损失。没有 validation 证据前，不直接把滑窗或 TTA 用于正式提交。

### P1：先建立更可靠的本地验证

增加一份不替代原固定 val 的 stressed 验证报告：

- 统计 test_1 与 train/val 的 RGB、亮度、对比度差异；
- 按 test_1 观察到的亮度方向构造轻度颜色扰动；
- 报告原始 val mIoU 和 stressed val mIoU；
- 另做基于图像相似度或场景特征的 group split，作为泛化参考。

stressed 验证是代理指标，不是官方 test 标签。它只能用于比较实验的相对鲁棒性，不能被描述为 test_1 真实成绩。

### P2：exp003 只验证训练时长

严格保持 exp002 的模型配方，只将训练目标延长到 60 epoch：

- MIT-B0；
- 输入 768；
- batch 2；
- 学习率 6e-5；
- AdamW，weight decay 0.01；
- CE，Ignore=0；
- 仅水平翻转；
- 相同 train.csv、val.csv 和随机种子。

当前已加入完整 checkpoint 和 `--resume`。从新的 exp003 目录开始训练；旧 exp002 只有模型权重，不作为严格的 epoch 30 续训起点。

判定：

- 若后半程仍稳定上升，保留更长训练作为新基准；
- 若 30 epoch 后很快平台或下降，保留 exp002 的 30 epoch；
- 无论验证集如何变化，都单独记录 test_1 提交结果，不能把排行榜变化归因给训练时长而不做本地对照。

### P3：exp004 只加入颜色与轻度尺度增强

如果 P0/P1 支持颜色域偏移，下一实验在确认的训练时长基准上加入：

- brightness/contrast；
- saturation/hue 或轻度 HSV 扰动；
- 轻度 gamma；
- 随机尺度和裁剪，以提升尺度鲁棒性；
- 保留水平翻转。

增强强度必须受控。航拍图中的颜色和纹理是类别线索，过强扰动可能损害 Water、Vegetation 和 Agricultural。垂直翻转是否合理需要结合航拍方向和验证结果，不能默认加入。

### P4：exp005 针对 Barren 和小类别

根据三联图确认 Barren 被误判成什么之后，先选择一个方案：

- CE + 温和 Dice；或
- 温和类别权重；或
- 对含 Barren 的样本做受控过采样。

不要三者同时使用。Vehicle 和 Barren 像素占比较低，但极端 inverse-frequency 权重可能造成大量误检，必须同时观察 Background、Building 和总 mIoU。

### P5：模型容量

只有在训练时长、颜色/尺度增强和推理策略已经形成稳定基线后，才比较 MIT-B1/B2。大模型无法直接修复颜色域偏移；它应是独立变量，不能与新 loss 或增强绑在一起。

## 4. 推荐实验表

| 编号 | 唯一主要变量 | 其他保持不变 | 目的 |
|---|---|---|---|
| inference-001 | 推理策略 | exp002 checkpoint | 判断 768、1024、滑窗的部署收益 |
| audit-001 | 验证协议 | 不训练 | 建立 stressed/group 泛化参考 |
| exp003 | 训练轮数 30 -> 60 | exp002 全部配方 | 判断是否训练不足 |
| exp004 | 颜色/轻度尺度增强 | exp003 确认的时长和其余配置 | 提升域鲁棒性 |
| exp005 | CE+Dice 或类别策略之一 | exp004 基准 | 修复 Barren/Vehicle，不混变量 |
| exp006 | MIT-B1/B2 | 之前确认的配方 | 判断容量收益 |

`batch size` 是资源和吞吐变量。先做不计成绩的显存/吞吐 benchmark，再决定是否作为独立实验；不能与 scheduler 和学习率线性缩放一起改。

## 5. 学习率调度的放置位置

scheduler 不放进 exp003。若 exp003 证明延长训练有收益，下一轮再单独加入一种 warmup + cosine 或 warmup + poly，并固定训练轮数、batch 和初始学习率。

原因是 GLM 建议的“batch 增大 + 线性放大学习率 + warmup + cosine + 60-80 epoch”同时改变了至少四个因素。这个方案可以作为后续组合优化候选，但不能作为第一个可归因实验。

## 6. 提交策略

- 当前 `0.591572` 作为 test_1 首版基线保存。
- 不用 test_1 分数逐轮刷参数；test_1 无标签，提交反馈只能作为低频外部参考。
- 每次提交前保存：checkpoint 路径、推理参数、zip 文件哈希、检查报告、提交时间和官方分数。
- 只有在推理策略或训练实验完成并通过本地验证后才提交关键版本。
- 关注官方基线和规则，特别是 Ignore 评分口径、zip 目录层级和 TTA/滑窗合规性。

## 7. 实验记录要求

每次实验至少保存：

- `run_config.json`；
- `history.jsonl` 和 `history.json`；
- `best_metrics.json`；
- `best_checkpoint.pt` 和 `latest_checkpoint.pt`；
- 原始验证 mIoU、每类 IoU、预测 Ignore 比例；
- stressed/group 验证结果（如果该实验已启用）；
- 推理策略、输入尺寸、窗口和 stride；
- 是否提交 test_1 以及官方结果。

结论必须写成“相对哪个基准、改变了什么、指标如何变化”。不要只写“效果变好”或“排行榜变差”。

## 8. 最终路线

当前最稳妥的路线是：

1. 先做 test_1 全量预测统计和三联图；
2. 用 exp002 checkpoint 完成 1024/768/滑窗验证对比；
3. 建立 stressed/group 验证参考；
4. 启动 exp003，保持配方不变，仅训练 60 epoch；
5. 再做 exp004 颜色与轻度尺度增强；
6. 根据 Barren 误判可视化选择 Dice、类别权重或过采样之一；
7. 最后再测试 scheduler、batch/吞吐和 MIT-B1/B2。

核心目标不是把某一次排行榜分数解释得很精确，而是建立一个能够区分“训练不足、域偏移、推理损失和类别不均衡”的实验链路。这样下一次提交即使没有立刻大幅提升，也能明确知道应该沿哪条路径继续。
